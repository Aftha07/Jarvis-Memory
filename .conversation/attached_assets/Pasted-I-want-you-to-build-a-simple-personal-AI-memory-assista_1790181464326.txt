I want you to build a simple personal AI memory assistant website called **JARVIS**.

IMPORTANT: This is NOT a CRM, ERP, accounting system, or complicated business management application. The main purpose is very simple: I am forgetful and I do not want to manually maintain notes every day. I should be able to simply speak or type something to JARVIS, and JARVIS should remember, organize, and retrieve it for me later.

## MAIN CONCEPT

The workflow should be:

**I speak/type → JARVIS understands → saves the original information → organizes it → I can ask about it later → JARVIS answers from my saved memories.**

The interface must be extremely simple and mobile-friendly.

---

## 1. MAIN SCREEN

Create a clean, modern JARVIS-style interface.

The main screen should primarily contain:

**JARVIS**

A message such as:

**"What should I remember?"**

Then:

- Large microphone button for voice input
- Text input box
- Send button

Do NOT create a complicated dashboard with many forms.

I should be able to use the website easily from my iPhone and Mac.

---

## 2. SAVING MEMORIES

Example:

I say:

"Jarvis, today I met Ahmed from ABC Company. He told me they may need 5 operators next month."

JARVIS should save the complete original statement.

It should also automatically understand useful information where possible, such as:

- Date/time
- Person
- Company
- Subject/topic
- Requirement
- Follow-up
- Category

However, NEVER lose or replace the original statement.

The exact original transcript is the most important record.

Every saved memory must automatically have:

- Unique ID
- Original text
- Created date
- Created time
- Updated date/time if edited
- Optional category
- Optional extracted information

---

## 3. REPEAT / VERIFY

This is extremely important.

After I save something, I need to be able to verify what JARVIS actually stored.

If I say:

"Repeat"

or:

"What did I just say?"

or:

"What did you save?"

or:

"Show my last note."

JARVIS must retrieve the latest saved memory and repeat the actual stored information.

Example:

Me:
"Today I met Ahmed from ABC. He needs 5 operators."

JARVIS:
"Noted."

Me:
"Repeat."

JARVIS:
"Today I met Ahmed from ABC. He needs 5 operators."

Do NOT treat "Repeat" itself as a new memory.

---

## 4. CORRECTING A MEMORY

I should be able to correct the last information naturally.

Example:

Me:
"No, change 5 operators to 8 operators."

JARVIS should understand that I am correcting the previous memory.

Update the current version while keeping the original information/history internally if possible.

Then reply:

"Updated. ABC requires 8 operators."

If I then say:

"Repeat."

JARVIS should repeat the corrected record.

---

## 5. ASKING JARVIS ABOUT OLD INFORMATION

This is the main purpose of the application.

Examples:

"What did Ahmed tell me?"

"When did I meet Ahmed?"

"What did I discuss with ABC Company?"

"Who asked me for operators?"

"What did I do yesterday?"

"What did I tell you last week?"

"Did anyone ask for a quotation?"

"I remember somebody asked for 5 operators. Who was it?"

JARVIS should search MY saved database records and answer based on them.

It must NOT invent information.

If there is no matching saved information, say something simple such as:

"I couldn't find anything about that in your memories."

---

## 6. VOICE

Voice is very important.

I should be able to press the microphone and speak naturally.

Example:

"Jarvis, today I visited ABC Company and met Mohammed. They asked me to send a quotation tomorrow."

Convert my speech into text.

Show me what was understood.

Save the text.

JARVIS should also be able to speak responses aloud.

For example:

"Noted."

or:

"You met Mohammed from ABC Company today and they requested a quotation."

Use free browser/device speech recognition and text-to-speech where possible so that there is no mandatory voice API cost.

If voice recognition is unavailable in a browser, text input must continue working normally.

---

## 7. REMINDERS

If my statement contains a reminder:

"Remind me tomorrow at 10 AM to call Ahmed."

JARVIS should recognize:

Task: Call Ahmed
Reminder: Tomorrow at 10 AM

Save the reminder separately but keep the original statement too.

Create the application structure so reminders can later work even when the website is closed.

Do not depend permanently on keeping the browser tab open.

For the initial version, clearly separate reminder storage/logic so server-side or push notification functionality can be added later.

---

## 8. DATABASE

Use **Supabase** for permanent cloud storage.

Keep the database design SIMPLE.

Suggested main tables:

### memories

Fields such as:

- id
- user_id
- original_text
- current_text
- category
- extracted_data JSON
- created_at
- updated_at

### reminders

Fields such as:

- id
- user_id
- memory_id
- reminder_text
- remind_at
- status
- created_at

Do not create 20 unnecessary tables.

Store text, not permanent voice recordings.

Voice should be converted to text and the text should be stored.

---

## 9. SECURITY

This is my personal memory and may contain private information.

Implement authentication using Supabase Auth.

A user must log in before accessing memories.

Use Row Level Security so one authenticated user can only access their own records.

Never expose Supabase service-role keys or other private server credentials in frontend code.

---

## 10. MEMORY HISTORY

Create a simple History section.

I should be able to see memories ordered from newest to oldest.

For example:

Today, 3:45 PM
Met Ahmed from ABC Company. They may need 5 operators next month.

Today, 11:20 AM
Paid SAR 500 for transportation.

Yesterday, 5:10 PM
Mohammed asked me to call him next week.

Include simple search.

Do not make this page complicated.

---

## 11. INTELLIGENT ORGANIZATION

JARVIS may automatically classify records into simple categories such as:

- Meeting
- Person
- Company
- Requirement
- Follow-up
- Payment
- Expense
- Task
- Idea
- Personal
- General

I should NOT have to manually select these categories every time.

If JARVIS is uncertain, simply save it as "General".

The original statement must always be saved regardless of classification.

---

## 12. DESIGN

I want a professional futuristic JARVIS-inspired design, but NOT an overly complicated sci-fi screen.

Use:

- Dark background
- Clean modern interface
- Subtle glowing elements
- Large central microphone control
- Smooth animations
- Excellent mobile layout
- Easy-to-read text

Keep functionality more important than visual effects.

It should feel like I am talking to my personal assistant.

---

## 13. MOBILE / PWA

Make the application responsive.

It should work properly on:

- iPhone
- Android
- Mac
- Windows

Prepare it as a Progressive Web App where practical so I can add JARVIS to my iPhone Home Screen and open it like an app.

---

## 14. COST

I want to keep this project free or within free tiers as much as possible.

Prefer:

- Supabase free tier
- Free hosting
- Browser speech recognition
- Browser text-to-speech
- Open-source/free components

Do NOT add paid APIs without telling me first.

If an AI API is necessary for advanced natural-language understanding, create the architecture so the AI provider can be added/replaced easily, but do not make the basic memory functionality dependent on an expensive API.

---

## 15. DATA SAFETY

Never delete a memory automatically.

Provide manual delete functionality with confirmation.

Keep the original transcript even when structured information is extracted.

If a correction is made, preserve enough history to know what was originally recorded.

Later I should be able to export all memories as CSV/JSON for backup.

---

## 16. MOST IMPORTANT RULE

The application must remain SIMPLE.

I do NOT want to maintain JARVIS.

**JARVIS should maintain my memories for me.**

I should normally only need to:

1. Open JARVIS.
2. Speak or type.
3. JARVIS saves it.
4. Ask JARVIS whenever I forget something.

Do not make me fill forms for normal memory entry.

---

## DEVELOPMENT REQUIREMENTS

Build this with a clean, maintainable structure that can also run locally in VS Code.

Use a modern React-based stack.

Keep environment variables in `.env`.

Provide `.env.example`.

Provide clear README instructions for:

- npm install
- local development
- Supabase setup
- environment variables
- database SQL/schema
- production deployment

Do not hard-code credentials.

Handle errors gracefully.

Do not lose user input if a request fails.

Before considering the project complete, test:

- Creating a memory
- Reloading and confirming it remains saved
- Repeat command
- Asking about an old memory
- Editing/correcting the last memory
- Search
- Authentication
- Voice input where supported
- Voice output
- Mobile responsiveness
- Database permissions
- Error handling

Start by creating the architecture and core memory functionality. Do not add unnecessary business-management features.

The final goal is:

**A simple personal JARVIS that I can talk to every day, that remembers what I tell it, and gives that information back to me whenever I forget.**
